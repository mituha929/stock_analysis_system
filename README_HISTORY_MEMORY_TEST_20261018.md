## 解讀與限制

- 本次未出現每查一檔持續增加上百 MiB；大幅增量集中首筆，後續私有記憶體大致穩定。這支持優先追查歷史連線初始化／重建的方向，而不是每檔斷線重建。
- 數據是整個 API 程序用量，包含 COM、原生配置、快取、序列化與其他背景活動，不是 1350 根資料的物件大小。
- 沒有熱修改服務或注入 session 追蹤：公用端點不提供 COM Session ID／重連計數。因此依短請求間隔及現有共用邏輯預期復用，但沒有直接證明全程 session identity 相同。
- 沒有分別量到 COM 初始化／關閉內部步驟、Python heap 或原生 heap；35 秒後亦未直接確認 session 關閉事件。既有快取 TTL 為 300 秒，本次尚未等所有快取過期，不能將閒置結果稱為所有資料已釋放。
- 有限樣本不能證明完全沒有洩漏，也不能代表全市場長時間回補、其他週期或 MySQL 寫入時的狀況。採樣峰值可能漏掉極短尖峰。
- 測試後確認正式回補仍為 paused、worker_active=false。

```powershell
.\.venv\Scripts\python.exe -B -X utf8 .\scripts\measure_history_batch_memory.py --pid 19640 --start 2026-10-10 --end 2026-10-16 --rounds 2
```
