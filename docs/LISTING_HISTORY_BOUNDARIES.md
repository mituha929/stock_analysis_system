# 掛牌日期與回補邊界

本功能讀取同一個 MySQL 的 `stock_master`；興櫃另唯讀使用官方基本資料，不另建股票主檔，不刪除或清理既有行情。API／CLI 共用同一回補引擎；程式更新後需自行重新啟動 API 才會生效，不會自動登入或啟動全市場重抓。

## 邊界規則

- 代號與市場精確對應：0／5 → TWSE、1／6 → TPEx、4 → 官方興櫃清單 ESB。指數、黃金或其他未涵蓋商品沿用原探查規則。
- 興櫃採官方 `mopsfin_t187ap03_R` 的 `DateOfListing`，不是成立日；同時精確核對現有代號及公司簡稱（只正規化空白及全半形，不猜名稱別名）。來源每日每程序最多讀取一次；欄位變動、失敗、日期不明或名稱不符時不限制歷史。此流程不寫入 `stock_master`，不影響原市場主檔。
- 只接受官方來源、已到掛牌日、日期狀態有效且仍在主檔最新名單的資料。NULL、未來日期、來源或欄位不符時，不推測日期、不以空值限制回補。
- 分鐘／日 K 包含掛牌當日，排除掛牌前日期。向前擴大查詢仍受同一邊界約束。
- 週／月 K 下限取掛牌所在週一／月初，保留該期標籤。由日 K 彙整時，來源日 K 從實際掛牌日開始查，產出的週／月標籤仍是週一／月初。
- 新計畫、已保存的舊計畫／舊斷點、日常根數回抓、假日日 K 缺口檢查與修補都套用同一規則。無須重設斷點，也不必先清空工作表。已經結案的舊工作不會僅因本次更新自行重跑。

## 轉上市與既有舊行情優先

上市日期不一定是同一股票最早的交易日。上市股票另外比對證交所公開的[最近上市公司](https://openapi.twse.com.tw/v1/company/newlisting)資料，以「代號＋實際上市買賣日期」精確核對，不能把查不到轉上市紀錄當成沒有轉上市。

- 同一代號、同一統編，且主檔保留有效的原市場掛牌日期時，可採較早的原市場日期；不僅憑名稱或代號相同就串接不同公司。
- 註記櫃轉市但原上櫃日期未知、股份轉換等來源有疑義，或上市來源日期比對不上時，不用現在的上市日截斷，保留原本歷史探查與補入上櫃行情的能力。
- 上市來源每天每程序最多讀取一次，限制回應大小與逾時。來源不可用時採保守回退；不覆寫 `stock_master`，也不為每檔股票打一次網路請求。
- 任一週期已有「早於掛牌所屬期間」的行情時，以既有資料為主，停用該商品的掛牌截斷。週一／月初標籤本身早於掛牌日，不算此種衝突。
- 寫入時，早於現在市場掛牌日的既有分鐘／日行情不覆寫 OHLCV、來源或寫入時間；缺少的舊資料仍可新增。保護寫入使用嚴格 INSERT＋重複鍵不更新，不用會吞掉資料錯誤的 INSERT IGNORE。
- 週／月以完整期間判斷：早於掛牌所在週／月的舊資料不改名、不覆寫，也不刪除別名。**掛牌所在週／月不屬於掛牌前資料**，即使週一／月初標籤較早，仍保留且可隨後續交易更新，不會把掛牌首週／首月凍結成暫定值。

## 掛牌歷史不足，不等於完整 1,200 根

到已確認的掛牌邊界仍未達目標時，工作沿用 `insufficient_history`，原因明確寫為「掛牌歷史不足」，保留實際筆數與原目標，不把 2 根改算成 1,200 根。保存初始化終止狀態，後續正常增量更新，不反覆重新初始化掛牌前範圍。

「已停止向前探查」不代表期間內沒有缺口。假日日 K 驗收仍須檢查掛牌日至截止日的交易日：空回應、掛牌日缺資料、期間缺口、未核實交易日曆，都不能自動宣告完整。僅當期間內無未解缺口、交易日曆已核實時，可列 `complete_available_history`，並在 `audit_json.history_limit_reason` 標示「掛牌歷史不足」。`first_trade` 仍只供原本人工核實的首次交易證據使用，不把一般掛牌日冒充首次歷來交易日。

已確認邊界前的舊缺口紀錄會保留在缺口表，標示 `confirmed_no_bar / before_confirmed_listing`，不再排入回抓；不刪除任何既有 K 線。

2026-10-26 依使用者要求可另以有完整備份、工作鎖及交易回滾保護的工具清空全部舊驗收／缺口，而非清空行情。詳見 [舊驗收清單重設](DAY_INTEGRITY_RESET.md)。清空後是「尚未驗收」，不是資料已完整。
