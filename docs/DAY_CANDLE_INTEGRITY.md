# 日 K 最近 1,200 根：日期驗收、缺口清單與補抓

## 本次變更

2026-10-21 依使用者要求改為「交易日正常抓取，休市日才完整驗收」。以下驗收與缺口規則保留，但只在允許的休市時段執行；不再每天以完整歷史驗收阻擋正常更新。

以原計畫的日 K 歷史目標（預設1,200根）驗收，與每日重新取得10根分開。
2026-10-24 後續調整：混合週期計畫先執行所有週期正常抓取，再執行待補齊／歷史補抓，最後才進行以下符合時段的日 K 驗收。逐商品讀取截止日前最後1,200個不同日期，檢查其中與尾端缺口。
不是 COUNT=1200、工作 completed 或畫面100% 就視為完整。
休市日手動續跑既有多週期計畫時，日 K 未通過驗收仍保留待查，但不再作為其他週期正常抓取的閘門。

## 交易日與休市日的分工

- 判斷使用**實際台北日期**，不是歷史計畫的截止日；預設 `CAPITAL_DAY_INTEGRITY_SCHEDULE=non_trading_days`。
- **交易日**：正常日 K 仍優先，其他週期正常輪接著執行，待補工作留到最後；不掃最近1,200根日期、不執行驗收清單的補缺請求。日 K 待補齊不再擋住其他週期。
- **週末／已確認的平日休市日**：每日排程沿用原時間（預設18:30）執行專用日 K 驗收與缺口補抓，不同步商品主檔、不建立其他週期工作、不重排原35組計畫。缺口尚未解決時，預設900秒後限量續跑，不是每15秒重驗一次。
- 平日休市狀態必須有官方年度快取或明確管理者休市設定；日曆尚未核實時不把平日當休市日。排程原本仍會嘗試下載當年度日曆。週末無須為判定資格而上網。
- 專用排程使用 `candle_day_integrity`／`candle_day_gaps` 原清單；進度另存於本機控制的 `day_integrity_maintenance`，不覆寫一般抓取的計畫、完成數、run_id、重試時間及斷點。
- 已知缺口不會因交易日略過驗收而變成「已完成」。查詢頁顯示各商品最後驗收結果與截止日，仍可唯讀查看／匯出。
- 跨入交易日後，在安全邊界停止新增驗收／補缺請求；已收到的資料先原子寫入並釋放 DLL 視窗。缺口與證據留待下次休市日接續。
- 共用 API／CLI 獨占工作鎖、記憶體門檻及使用者安全暫停；既有工作忙碌則稍後重試，不搶占、不偷偷登入或重啟。
- 自動功能隨 `CAPITAL_DAILY_BACKFILL_ENABLED=true` 啟用，API 需持續運作且使用者先登入；關閉每日排程或未設定 day 時，不另啟動休市日任務。手動日 K 批次仍依實際日期判斷是否驗收。

`CAPITAL_DAY_INTEGRITY_SCHEDULE=always` 僅供明確的診斷／隔離測試覆寫，會恢復每次批次都驗收，不是平常建議設定。停用總開關時，兩種時段都不驗收。尚無實測全市場驗收時間，不宣稱假日一定能補齊來源不存在／仍未知的資料。

適用 API、每日排程及 CLI 共用的批次 runner。明確指定固定起訖日的批次工作不會被擅自擴成1200根驗收；未選 day 不會新增日 K 工作。休市日專用排程是獨立的日期驗收，不重排或擴張固定範圍工作本身。
原始 candle、已存斷點、資料錯誤五次隔離、單一工作鎖、記憶體保護及 DLL 提交後輪替都保留。
TSLQ 仍排除。測試及程式修改不代表正式資料已補完。

## 空回應不再一律等24小時

- 日 K 向前查詢使用14、30、60、120、240、480、960、1920日曆日的逐步擴大區間，上限仍受 `CAPITAL_KLINE_MAX_DAYS_DAY` 約束。
- 一般回抓以原游標向前推進、不重複計入之前取得的日期；超額有效資料照常保留／覆寫。
- 每檔、整輪請求預算仍有上限。空區間不等於「不存在」，保留下一日期，預設15分鐘後繼續，而非直接等24小時。
- 日 K 驗收另依持久化日期清單補抓，每輪預設最多30個區間，且不突破原回補的整輪預算。其他日 K 商品也有處理機會。

## 什麼可以證明無須有 K 線

1. 週末、已載入的官方年度休市快照、明確管理者休市設定。
2. 既有官方停復牌來源核實的完整停牌日。
3. 經人工核對官方公告的首次交易日，或精確商品／日期的無成交證據。

初次驗收會嘗試補下載範圍涉及年度的官方休市表。下載失敗、年度資料未確認，會顯示 `calendar_unverified`，不拿「週一到週五」冒充已驗證交易日。
已存 K 線若與休市或首次交易日證據衝突，列為 `calendar_conflict`／`evidence_conflict`，不刪除既有資料、不自行修正日期。

不以「最早一筆 K 線」「連續幾次空回應」「資料庫根數較少」推定掛牌日起點。
官方 [ISIN 清單](https://isin.twse.com.tw/isin/e_C_public.jsp?strMode=2) 可供查詢線索，但市場掛牌／轉板日期未必是商品首次交易日，須核對公告及市場轉換歷史後才能作為排除依據。
程式不會僅驗證網址就自動認證公告內容；未核對的情況維持未解決。

`config/day_candle_evidence.json` 預設空白，不內建猜測日期。每筆人工核實證據格式如下，實際使用時必須填入已核對的真實公告連結與說明，不能照抄示意資料：

```json
{
  "version": 1,
  "records": [{
    "market_no": 0,
    "symbol": "經核對的商品代碼",
    "kind": "first_trade",
    "start_date": "2026-10-19",
    "end_date": "2026-10-19",
    "source": "https://www.twse.com.tw/請替換為實際公告路徑",
    "reason": "核對公告及市場轉換紀錄後確認的首次交易日，非轉板日期",
    "reviewed": true,
    "reviewed_on": "2026-10-20"
  }]
}
```

`first_trade` 僅接受市場0、1、4；其首次交易日可供對應5／6的歷史邊界核對。
`no_trade` 可用0、1、4、5、6，但整張無成交證據不套用到零股，須精確指定市場與起訖日期。
只接受證交所／櫃買 HTTPS 網域、精確代碼、合法日期及明確已核對標記。
證據矛盾時不使用；相同股票在較早市場交易的歷史不能因轉板日期被遮掉。

## 驗收狀態

也會讀取 `stock_master` 的可靠掛牌邊界，限制查詢、擴大範圍及缺口清單。轉上市與舊行情優先保留；不把一般掛牌日期冒充人工首次交易證據。詳見 [掛牌日期與回補邊界](LISTING_HISTORY_BOUNDARIES.md)。

| 狀態 | 含義 |
| --- | --- |
| `complete` | 指定歷史目標達標，範圍內缺日期已解釋，且年度日曆已核實 |
| `complete_available_history` | 已核實首次交易日或適用掛牌邊界起的全部可用日 K；不足1,200根，另列，不宣稱達到1,200根；掛牌邊界情況另標「掛牌歷史不足」 |
| `unresolved` | 有具體日期尚待查證／補抓 |
| `history_shortfall` | 目標未達，不能僅因查詢下限就宣稱不存在；後續擴大搜尋 |
| `calendar_unverified` | 年度交易日曆未核實 |
| `calendar_conflict`／`evidence_conflict` | 已存資料與證據衝突，需查證，不自動刪資料 |

資料異常第5次可將某個缺口標為 `failed_data`，繼續處理其他日 K 商品，但不讓整體日 K 假通過完整性驗收。
未知空回應永遠不會被轉成已核實無成交。
不以零成交量、複製前一天收盤價或改符號方式製造 K 線。

## 清單、寫入與重開

新增兩個 InnoDB 表，首次由新 runner 在工作鎖下建立，不變更既有 K 線欄位：

- `candle_day_integrity`：每表／市場／商品的截止日、目標、搜尋起點、驗收狀態與證據。
- `candle_day_gaps`：逐日期待查、已補回、已核實無 K、資料異常隔離、查詢次數與下次重試時間。

每個補抓區間的有效 K 線 upsert、缺口狀態及重試資訊在同一交易提交。
寫入失敗一併回滾；提交後才通知 DLL 可釋放／輪替。相同時間鍵覆寫，其他歷史保留。
重開後從 MySQL 清單與原斷點接續；先前的空回應不會在重開後變成已完成。

`GET /api/v1/backfill/day-integrity?markets=all&limit=200&offset=0` 唯讀列出尚未解決商品與日期。
回傳 `items`（逐日期）與 `assessments`（包含日曆不明、證據衝突等可能沒有單一缺日的商品）。
`include_resolved=true` 可查看已補回／核實無 K 的歷史。清單以各商品最後一次驗收為準，尚未驗收或不同截止日的紀錄不能當作當日全市場已通過。
GET 不建表、不登入、不抓群益、不寫 K 線。大清單使用 limit/offset，最大1000筆／頁。

`/data-status` 新增「查看／更新日 K 缺口」、上一頁／下一頁；僅按按鈕讀取，不增加自動輪詢。
原表格15秒、本機進度5秒保留；2秒輪詢不會恢復。

可唯讀匯出全部分頁（新檔案、限專案output內、逐頁串流避免大清單累積記憶體）：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts\export_day_candle_gaps.py --output output\day-gaps-report.json
```

匯出不是對運作中 worker 的凍結快照；持續補抓時，各分頁可能不同時間，需以最終停止後的驗收結果判斷完整性。
