# V3.10～V3.11：AI 選股預覽與確認

實作日期：2026-10-30。入口為 `/v3#ai`，左側「07 AI 選股」。

已完成引導式網頁與後端確認流程；實際 Ollama 與正式股票資料的整體驗收尚待完成。本次未重啟正式服務、登入群益或觸發回補。

## 使用方式

1. 安排正式服務安全重啟後，開啟 `http://127.0.0.1:8000/v3#ai`，必要時按 Ctrl+F5 更新靜態檔案。
2. 選擇市場、指定股票或自選股，並設定日／週／月 K 與歷史資料表。第一版預設上市＋上櫃、日 K、`candles`。
3. 輸入完整條件，例如「股價高於MA20，且RSI不超過70」，按「解析條件並預覽」。這一步只解析，不選股。
4. 核對原文、範圍、白話條件、全部／任一分組、假設及排序。模型未列假設，也仍須自行核對語意。
5. 可在預覽區修改數字門檻，再按「套用修改，重新產生預覽」。舊確認立即失效；原文保留對照，實際條件以最新預覽為準。欄位、運算子或股票範圍變更，請修改完整輸入／設定後重新解析。
6. 勾選兩個確認項目，再按「確認條件並開始選股」。只讀 MySQL，不逐檔呼叫 AI、不向群益抓取資料。
7. 查看符合結果、逐條理由與警告、K 線日期、臺北時間的寫入時間及資料排除原因。

「找會賺錢、一定上漲」先要求釐清；新聞、財報、持股減碼等目前不支援。範例按鈕只填入文字，不會直接執行。沒有結果也不自動放寬條件。

目前是完整需求的一次解析流程；不支援「再加上剛才的條件」等多輪策略修改。頁內文字修改紀錄不保存到資料庫或 localStorage。

## 預設值與執行保護

| 項目 | 行為 |
|---|---|
| 週期 | 只開放 `day`、`week`、`month`；分鐘 K 尚未開放 |
| 分析歷史 | 預設360根，20～2000根；這是讀取分析範圍，不修改回補目標或刪除舊資料 |
| 顯示數量 | 預設20檔，1～1000檔；顯示截斷不等於掃描部分完成 |
| 掃描時間預算 | 預設120秒，1～300秒；在逐檔邊界檢查，不能強制中止已在執行的單次 SQL |
| 排序 | 符合條件數由大到小 → 技術方向分數由大到小 → 風險分數由小到大；也可選風險或代號 |
| 預覽 | 記憶體內最多64份、有效10分鐘、單次執行；服務重啟或資料應有期間改變須重做預覽 |
| 版本 | 綁定原文、規則、全部執行設定、假設與固定自選股清單，不能拿舊版本換新條件 |
| 互斥 | 與既有手動／儲存策略選股共用掃描鎖；忙碌回傳409，不消耗有效預覽 |
| 重試 | 執行不自動重試；成功或執行中資料庫失敗均消耗預覽，重跑前須重新確認 |

前端會阻擋連點、丟棄過時的解析回應；修改輸入後隱藏舊結果，避免把舊結果當成新需求的答案。HTTP 等待逾時不代表伺服器工作已取消。

數字門檻、欄位、深度及型態仍使用既有驗證；額外攔截明確同欄位矛盾與單位未確認的原始成交量／OBV條件。關鍵字攔截與規則驗證無法保證理解所有自然語句，人工預覽仍不可省略。

預覽憑證不是登入或成員權限。第一版沒有新增帳號隔離；原有人工選股 API 仍保留相容行為。

## 資料品質

- AI 選股路徑先讀取可確認完整的 K 線，再進行條件判斷；既有人工選股 API 不默默套用這個新政策。
- 使用現有臺灣交易日曆，採臺北時間14:00的保守收盤界線。日 K 對照最近已完成交易日；週／月 K 對照最後已完成交易週／月，最後交易日收盤後即可使用當期。
- 每根資料分別檢查 K 線日期及 `fetched_at`。週／月資料寫入時間須在該期間最後交易日14:00以後，避免把早期快照當完整資料；空寫入時間不作完整證據。
- `fetched_at` 無時區時依既有資料庫約定解讀為 UTC。畫面另列臺北寫入時間；資料日期不因寫入很新就變成最新。
- 最新完整期間落後，分類為 `stale_data`；全部是無法確認的快照則為 `unverified_period`；沒有資料為 `missing_data`。有效歷史不足以算條件時另列 `insufficient_data`。
- 停牌證據只讀現有本地官方快取，且須當日成功取得及有對應日期紀錄；不在選股中上網更新。沒有可信證據時顯示個股狀態無法確認，不能推定正常交易或已停牌。
- 以上驗證不保證供應商數字正確，也不證明每個歷史交易日都無缺口；不會補造 K 線。
- 零股表沿用目前專案資料來源，不能據此宣稱歷史資料一定是純零股成交 K 線，介面會顯示限制。

結果區分「掃描完成」「部分完成」「顯示筆數限制」。掃描完成只代表範圍內每檔已處理，不表示每檔都有可分析資料，也不表示沒有被排除的股票。

## 新增 API

前綴 `/api/v1/ai/rules`；原 `/parse`、`/validate` 保留。

| 方法／路徑 | 用途 |
|---|---|
| POST `/preview` | `{text, history_interval, settings, replaces?}`，回傳白話樹、假設、未解決條件、資料政策及預覽版本；未釐清時沒有可執行憑證 |
| POST `/preview/revise` | `{preview_id, revision, rule}`，驗證新規則、撤銷舊版本並回傳新預覽 |
| POST `/preview/invalidate` | `{preview_id, editable?}`，修改輸入時撤銷；`editable=true` 只保留重做門檻預覽能力，不能直接執行 |
| POST `/execute` | `{preview_id, revision, text, settings, confirmed:true, assumptions_confirmed:true}`，後端再驗證且原子消耗版本，只讀取 MySQL |

`settings` 包含 `universe`、`history_interval`、`candle_table`、`history_bars`、`limit`、`timeout_seconds`、`sort`。額外未知欄位遭拒絕，不能指定模型 URL、SQL 或執行程式。

預覽回應的 `data_policy.expected_period_end` 與執行回應的 `data_quality` 供核對應有日期；完整設定快照在 `confirmed_preview`。資料品質狀態在 `excluded` 與 `excluded_counts`，未處理清單在 `remaining_symbols`。

Ollama 沿用現有 `.env` 的 `OLLAMA_*`，prompt版本為 `v3.10-1`；無須新增資料庫欄位或回補設定。只在解析收到請求時呼叫模型。多程序部署的預覽及掃描鎖目前不共用，請沿用單一 FastAPI worker；跨 worker 需要另做共用儲存與鎖。
