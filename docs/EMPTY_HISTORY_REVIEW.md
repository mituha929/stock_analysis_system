## 休市日

- 一般回補、既有斷點續抓、日 K 缺口驗收共用 `data/stock_market_holidays.json`，包含已確認的全市場臨時休市；上市／上櫃／興櫃及對應零股沿用股票市場日曆。
- 保留歷史週六補行交易例外。沒有歷史來源時，不能自行把 2019 年前的星期六排除。
- **不直接套用**臺北市停班停課名單；僅停課、部分地區或部分時段不等於全市場全天休市。須先確認交易所公告，再維護台股休市人工檔。
- 全區間皆休市就不向群益請求；日／分 K 查詢裁掉休市邊緣。大範圍查詢保留內部休市日期範圍，以免拆成數千次個別請求；這些日期不另外排缺口重試。
- 週／月區間只要有交易日便保留完整期間標記，不因週一或月初休市而刪掉整根 K。既有行情不因新日曆被刪除；與日曆衝突的資料留待查證。
- 不擴大已確認的掛牌起點；轉市場與既有掛牌前行情保護維持原設計。

人工日期維護後執行 `scripts/manage_stock_market_holidays.py build`。新版 runtime 依檔案修改時間重新載入，日曆熱路徑不下載網頁。超出十年快照範圍時沿用既有官方年度快取／設定；沒有可靠資訊不擅自認定某檔沒有交易。

## 有效空回應的定義

正常回補必須收到群益完成訊號、沒有逾時／斷線／解析／負成交量等錯誤，且原始結果確實為空，才記錄一次空觀察。週月彙整須來源日 K 請求均成功。因未完成期間、掛牌邊界或排除規則而過濾成空，不冒充來源空回應。

日 K 缺口檢查會針對已有紀錄的**缺少日期**記錄觀察；擴大區間收到其他日期的 K 線，不代表該缺口已解決。實際取得的有效資料仍正常寫入。

一般空回應也按個別候選交易日記錄；週／月以完整週／月為穩定鍵，未結束期間不累計有效天數。隔天查詢視窗移動或改用另一工作編號時，同一缺少日期仍共用觀察日，不能因查詢起迄日變動而歸零。查詢區間及原工作斷點另外保存在證據中。

```dotenv
# 允許 3、4、5；未設定預設 5。只修改 .env.example，不改你的 .env。
CAPITAL_EMPTY_REVIEW_TRADING_DAYS=5
CAPITAL_STOCK_HOLIDAY_FILE=./data/stock_market_holidays.json
```

觀察以臺北時區、不同交易日計算，非日曆天、非總嘗試次數，也不是從歷史 K 線日期開始算。採保守條件：查詢目標不晚於當日，且觀察當日正常／零股時段結束（14:30）後才計入。週末、已確認休市日、同一天重試均不增加天數；當日交易日曆尚未核實時也不計數，保留等待更新來源。下一次預約為下一交易日 14:35。

尚未達門檻：空區間與原斷點保留，延後重查；同市場其他商品與其他週期的正常抓取照常執行。2026-10-24 後續流程改成所有週期正常輪結束後才處理待補齊；未完成日 K 不再阻擋其他週期。這不會把空回應當成沒有歷史的證明。

達門檻：觀察列 `pending_review`，一般工作 `waiting_review`，日 K 缺口 `pending_review`。不移動該缺口的斷點、不寫零價／零量、不計為完成／失敗／掛牌歷史不足，也不宣稱已補齊 1,200 根。停止自動重抓，其他商品及其他可執行週期可繼續；全部可執行工作結束時顯示「空資料待查證」，而非資料完整。新日常回抓可先保存較新的資料，遇到舊待查區間才停止。

重新規劃、API 重啟、按續跑不會清除觀察天數；強制規劃也不直接解除待查狀態。已存在的總 `attempt_count` 不能換算成有效天數；本次不回填／猜測舊工作之前已失敗幾天。

## 查詢與匯出

重啟新版後使用唯讀端點：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8000/api/v1/backfill/empty-reviews?markets=all&limit=200&offset=0'
```

保留市場、商品、週期、日期區間、首次／末次有效回應時間、不同觀察日清單、原斷點、來源／掛牌證據、最後錯誤與錯誤次數。首次錯誤尚無有效空觀察時，仍由原工作錯誤／資料異常紀錄保存；不因此創建假的有效空回應。查詢為分頁 SELECT，不建表、不登入、不抓行情。資料表尚未建立時回傳 `storage_ready=false`，不是「所有資料皆正常」。

查詢回傳的 `counts` 是整個所選範圍（不是當頁）統計：`symbols` 去重商品數、`dates` 缺少日期數、`periods` 週月期間數、`records` 缺口紀錄數。同一商品在多週期／重試出現不重複算商品，同一日／分 K 商品日期不重複算日期；不同市場／整張與零股仍是不同商品。週月標記不是單一交易日，另計期間。控制狀態提供 `pending_review_symbols`／`pending_review_dates`／`pending_review_periods`；舊 `pending_review` 保留為紀錄數，不能當成商品數。

交給人工／AI／LLM 的 JSON：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts\export_empty_history_reviews.py --output output\empty-history-review.json
```

輸出路徑必須是 `output/` 中的新檔。匯出只讀 MySQL，不使用外部 LLM、不送出帳密；不會自動採納 AI 的判斷。審核應檢查官方休市公告、個別停復牌公告、可靠掛牌／首次交易證據及來源是否有資料供應問題；單靠空回應次數不構成「無交易」證據。沒有證據的項目保持待查，不可改成完整。確認全市場休市後維護休市人工檔；個股日 K 無成交證據沿用 `config/day_candle_evidence.json` 的人工核對契約。

## 人工要求重試一筆

先檢閱匯出證據，再針對端點中的 `id` 明確操作；不是自動重新登入或解除整批工作：

```powershell
.\.venv\Scripts\python.exe -B -X utf8 scripts\retry_empty_history_review.py --id 123 --reason '已檢閱來源，要求重新確認此區間' --allow-retry
```

工具取得既有 API／CLI 共用 worker 鎖，若有人抓取就失敗，不打斷工作。只將指定紀錄設為 `retry_requested`、釋放相符的等待工作／日 K 缺口；行情、收到根數與斷點不變。沒有自動啟動 worker／登入，之後自行續跑。舊觀察日不清空：再度空回應便回到待查，避免又無限循環五天。即使已有新證據，仍須透過重試／驗收流程核對，不能直接假造完整。
